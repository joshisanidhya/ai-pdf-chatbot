# SAGE repository audit

Audit date: 2026-11-22. Scope: tracked application source, manifests, examples, and deployment instructions in this checkout. No production credentials, MongoDB, deployed service, user corpus, or representative PDF corpus was available, so runtime behavior beyond static code paths is marked unmeasured.

## Architecture and traced flows

- **Sign in:** React stores JWT and profile in `localStorage`; Axios attaches a bearer token. Express verifies JWT and reads the user from MongoDB on every protected request. Passwords use bcryptjs at 12 rounds. There is no refresh/revocation mechanism.
- **Upload and indexing:** Multer writes uploads under a user directory. `uploadDocument` creates a Mongo document, then synchronously awaits PDF extraction, chunking, local transformer embedding, and a `MemoryVectorStore` build before returning HTTP 201. The browser progress bar only measures network upload; it switches to a generic processing message at 100%.
- **Question and response:** Chat checks document ownership and readiness, loads/creates a conversation, reconstructs the vector store if absent, retrieves up to four chunks, sends the full recent history and retrieved context to the configured LLM, then saves the whole conversation and document query count. LLM output is not streamed.
- **Restore/delete (original design):** Vectors were only in a process-local Map. A restart reparsed and re-embedded a PDF during its first query. Owner-scoped disk snapshots now avoid that work for indexed PDFs on durable storage. Related conversations are still not deleted with documents and can remain as orphans.
- **Frontend:** Vite/React SPA, all routes eagerly imported, Framer Motion throughout the UI, Markdown and syntax highlighting in chat. No frontend tests or measured bundle/CWV data are present. API uses Axios; upload uses its progress callback.

## Findings

| Severity | Area / evidence | Impact | Recommended fix |
|---|---|---|---|
| **Critical (fixed in first batch)** | `backend/server.js` mounted `express.static` at `/uploads`; any known URL was served without auth. | Private user PDFs could bypass application authorization. | Public static serving has been removed. Add only an authenticated owner-checked route if product needs file preview/download. |
| **High (partially fixed)** | `backend/middleware/upload.js` initially trusted MIME and extension only. | A non-PDF payload could be passed to a parser; parser/resource abuse remains possible within configured size. | Server now checks `%PDF-` in first 1024 bytes and tests invalid bytes. Parser resource limits and malformed/oversized PDF test coverage remain open. |
| **High (partially fixed)** | `backend/rag/ragPipeline.js` uses `MemoryVectorStore`; original restore reparsed/re-embedded on cache miss. | Restart incurred model and CPU costs; volatile vectors could disappear. | Single-flight and owner-scoped local disk snapshots are implemented. Ephemeral disks, larger-document memory use, and multi-host coherence still need work. |
| **High** | `backend/controllers/documentController.js` awaits CPU-heavy parse and sequential embeddings in the HTTP upload request. | Long requests, poor timeouts, event-loop pressure, and no useful processing status polling. | Move processing to a bounded background worker or job queue; keep a simple in-process queue for single-instance deployment if restart behavior is handled. |
| **High** | `backend/rag/embeddingService.js` loops over each chunk one at a time. | Slow ingestion for large PDFs; no chunk batching or concurrency controls. | Benchmark bounded batch embedding; retain memory limits and one shared model instance. |
| **High (fixed in first batch)** | JWT secret was not validated at startup and the example included a known placeholder. | Misconfiguration could enable predictable signing or fail at runtime. | Server now rejects missing/placeholder secrets and requires 32 characters in production. |
| **High (fixed in first batch)** | Production responses exposed raw 5xx errors and provider failure details. | Internal/provider details could leak to clients. | Server now returns generic 5xx messages and sanitized LLM provider failures. |
| **High (fixed in first batch)** | Question prefixes, retrieved excerpts, and provider response bodies were logged. | Sensitive document content and prompts could persist in logs. | Content-bearing logs were removed; request identifiers/provider status remain. |
| **High (mitigated in first batch)** | Retrieved document text was embedded inside the system prompt. | Prompt-injection text could be mistaken for trusted instructions. | Policy remains in system role and evidence/history are labeled untrusted; this reduces risk but cannot guarantee model behavior. |
| **Medium (partially fixed)** | Original pipeline used synchronous file reads and concatenated text without page metadata. | Disk reads blocked the event loop; citations could not identify original pages. | Async reads and page-aware chunks are implemented for newly processed text PDFs. Older indexes need reprocessing; OCR/scanned-page support remains absent. |
| **Medium** | `backend/models/Conversation.js` embeds unlimited messages and source text in one MongoDB document. | Conversation growth approaches MongoDB document size limits and every chat saves a growing array. | Bound history and migrate messages to a separate collection if long conversations are a product need. |
| **Medium** | `backend/controllers/conversationController.js` and document list accept unbounded page/limit values; several ID params are not prevalidated. | Expensive queries and avoidable cast-error responses. | Clamp pagination and validate ObjectIds. |
| **Medium** | `backend/controllers/documentController.js` document deletion does not delete conversations; user document count uses a decrementing `$inc`. | Orphaned history and possible count drift. | Delete or retain conversations by explicit policy; derive/repair count or make lifecycle atomic. |
| **Medium** | `backend/server.js` has global IP rate limit only, broad development origins, 10 MB JSON body, and no upload/chat-specific limits. | Cost abuse and avoidable API exposure under shared NAT; JSON body exceeds normal chat needs. | Add route-specific limits and production CORS allowlist; reduce JSON limits; consider user-level quotas. |
| **Medium (partially fixed)** | `backend/tracing.js` previously initialized OTel and a local exporter on every process start; `backend/package.json` still includes broad auto-instrumentation. | Unconfigured exporter noise and dependency/runtime overhead. | Tracing is now opt-in with an explicit collector endpoint. Dependency and enabled-mode instrumentation breadth remain to be reviewed. |
| **High (partially fixed)** | Initial backend `npm audit` reported 44 advisories. Unused dependencies were removed and compatible fixes applied; current audit reports 25 (0 critical, 10 high, 15 moderate). | Remaining vulnerability paths may affect runtime security; exploitability depends on usage. | Test breaking LangChain/transformer/telemetry upgrades in a separate batch. Backend `npm ci` now works with its documented legacy peer configuration. |
| **Medium** | `backend/rag/ragPipeline.js` rejects extracted text under 100 chars without OCR fallback. | Scanned PDFs fail; concatenated text loses page references. | Detect text density per page and report OCR unsupported clearly, or add OCR only after benchmarks. |
| **Medium (fixed in first batch)** | `frontend/src/App.jsx` eagerly imported every route; chat renderer loaded syntax highlighting with chat route. | More JS on landing/auth initial load and a large chat chunk. | Routes and Markdown renderer are now lazy-loaded; compare final build chunk sizes in `RESULTS.md`. |
| **Low** | README says “production-grade,” “strict vector retrieval,” and “real-time” despite no persistent vector index, page citations, or streaming. | Expectations exceed implementation. | Align product claims with verified behavior. |

## Per-stage inspection status

Authentication and ownership filters were inspected in route/controller code. Document and conversation lookups generally scope reads by `req.user._id`; chat feedback also scopes its conversation. Upload storage creates user directories. The public static file mount was removed in the first implementation batch. No account deletion endpoint or PDF download route exists. Conversation restore is Mongo-backed, but vector restore is not. No production deployment manifests or CI workflow were found. Two legacy root-level scripts execute model work and are not safe CI tests; focused Node test-runner coverage now exists for upload signature validation and production error sanitization.

## Benchmark status

No representative test PDFs or configured database/provider were present in the project. No paid LLM requests or large embedding runs were made. Reproducible benchmark commands and measurement limitations are in `BASELINE.md`; actual values remain explicitly unmeasured.
